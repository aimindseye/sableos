## Scope

S1.2 restores only the pure B2 power semantic contract into the Android 14 oxynoded source tree.

Restored semantics include:

- `PowerSource { Battery, Usb, Ac, Wireless, Unknown }`
- `PowerState { battery_percent, charging, source }`
- `PowerError`
- `PowerBackend` / `PowerService`
- capacity validation
- status mapping
- bramble observation-to-semantic mapping
- source precedence
- host unit tests

Explicitly excluded from S1.2:

- no sysfs or device reads
- no filesystem hardware backend
- no `sable-powerd`
- no Binder/HIDL/AIDL
- no radio/network access
- no SELinux policy change
- no init privilege change
- no physical flash

## Build-gate wrapper corrections

Two failures occurred in the temporary validation wrapper before the Android build started:

1. `set -u` caused `build/envsetup.sh` to fail on initially-unset `TOP`.
2. Re-enabling nounset before `lunch` caused a second failure on unset `version`.

The temporary wrapper was corrected to use `set -eo pipefail` while interacting with AOSP `envsetup.sh` / `lunch`.

These were audit-wrapper defects, not SableOS source/build failures.

## Android Rust lint correction

The first actual Android build reached Rust compilation but failed because AOSP compiles the target with `-D warnings`, and the intentionally staged power API was not yet consumed by the runtime daemon.

The errors were dead-code diagnostics for the staged semantic API.

The correction was deliberately narrow:

```rust
// S1.2 compiles the pure power contract before a runtime backend consumes it.
// Keep dead-code suppression scoped to this staged module only.
#[allow(dead_code)]
mod power;
```

No global warning suppression was added to Soong. No device-I/O surface or privilege was added.

Covered behavior includes:

- capacity boundaries accepted
- invalid/non-numeric/negative/out-of-range capacity rejected
- `Charging` / `Full` => charging true
- `Discharging` / `Not charging` / `Unknown` => charging false
- unexpected status => explicit error
- `dc` has highest precedence => `Wireless`
- `pc_port` or `usb` => `Usb`
- charging with no online source => `Unknown`
- unplugged non-charging => `Battery`
- bramble mapper never emits `Ac`
- `PowerService` forwards backend state and errors
