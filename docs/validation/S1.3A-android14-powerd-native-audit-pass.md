## Android 14 physical power-node evidence

The currently booted SableOS Android 14 bramble product remained:

- product: `sable_bramble_s1`
- build ID: `UP1A.231105.001.B2`
- SELinux: Enforcing

The five B2 bramble power nodes were present and readable through ordinary ADB shell:

- `/sys/class/power_supply/battery/capacity`
- `/sys/class/power_supply/battery/status`
- `/sys/class/power_supply/dc/online`
- `/sys/class/power_supply/pc_port/online`
- `/sys/class/power_supply/usb/online`

All five were labeled `u:object_r:sysfs_batteryinfo:s0` on Android 14.

Observed values during the audit were consistent with a fully charged device connected through the PC/USB path. Those instantaneous values are not treated as a permanent baseline; the important result is node existence, readability, and SELinux labeling.

## Android 12 held reference

The held Android 12 source still contains the prior `sable-powerd` reference implementation and vendor policy. It is retained only as design history and must not be copied blindly into Android 14.

The held reference confirms the earlier architecture used:

- `/vendor/bin/sable-powerd`
- a vendor-side SELinux domain
- `sysfs_batteryinfo` read access
- the same five hard-coded power-supply paths

## Android 14 conclusion

S1.3A establishes that the B2 physical observation surface remains available on the Android 14 bramble baseline and that the existing platform label is still `sysfs_batteryinfo`.

The next stage is deliberately split:

1. **S1.3B** — prove Android 14-native Rust vendor binary and vendor init placement with host tests, but do not package into the product and do not add SELinux policy yet.
2. A later policy/package gate will introduce the vendor non-coredomain helper boundary and only the minimum read-only sysfs permissions required by physical evidence.

This preserves the architecture rule that `oxynoded` itself does not gain direct sysfs access.
