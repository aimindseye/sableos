# S1.3B Android 14 native `sable-powerd` build proof — PASS

Date: 2026-08-30

## Scope

S1.3B validates only the Android 14-native Rust build and vendor placement mechanism for the narrow bramble power observation helper. It does not add SELinux policy, does not add the helper to `PRODUCT_PACKAGES`, does not enable the init service, does not build a full image, and does not flash a device.

## S1.3A evidence carried forward

The Android 14 bramble baseline exposes the same five required read-only power-supply nodes used by the B2 semantic contract:

- `/sys/class/power_supply/battery/capacity`
- `/sys/class/power_supply/battery/status`
- `/sys/class/power_supply/dc/online`
- `/sys/class/power_supply/pc_port/online`
- `/sys/class/power_supply/usb/online`

All five were observed on the physical Android 14 device with SELinux type `sysfs_batteryinfo` while SELinux was Enforcing.

## Rust source validation

The helper source is intentionally narrow:

- exactly the five approved sysfs paths
- read-only `std::fs::read_to_string` access
- no `/dev` access
- no Binder/HIDL/AIDL
- no radio/network/socket surface
- no command execution
- no `unsafe`/FFI surface
- raw observations only; charging/source semantics remain in `oxynoded`

Android 14 Soong rejected a vendor `rust_library` dylib and explicitly required an rlib. The build description was corrected to `rust_library_rlib`, leaving the vendor `rust_binary` unchanged.

Clippy under AOSP `-D warnings` then identified two boolean-assert style issues in host tests. They were corrected to `assert!` forms. The test-only approved-path constant was also scoped with `#[cfg(test)]` to avoid non-test dead-code warnings.

## Staging boundary

The init service remains explicitly `disabled`.

No `sable-powerd` SELinux policy is present yet.

`sable-powerd` is not present in `PRODUCT_PACKAGES`.

No full image build was performed and no device flash was performed.

The current long-running helper behavior is only a build-stage stub: after a successful startup observation it sleeps. IPC, retry/error policy, and final daemon behavior remain later gates and are not claimed complete by S1.3B.
