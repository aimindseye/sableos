# SableOS S1.1 Android 14 oxynoded physical validation

Status: PASS

## Baseline

- Product: `sable_bramble_s1`
- Device: `bramble`
- Android: 14
- Build ID: `UP1A.231105.001.B2`
- SELinux: Enforcing

## Physical write and boot

The controlled S1.1 flash completed successfully using `fastboot flashall` without `-w`.

Observed physical results:

- Android booted to the lock screen.
- Unlock succeeded.
- Userdata was not intentionally wiped by the S1.1 write procedure.

## oxynoded runtime validation

Init state:

- `init.svc.oxynoded=running`

Runtime process evidence:

- Process present and stable across a 5 second interval.
- SELinux process domain: `u:r:oxynoded:s0`
- UID: 1000
- GID: 1000
- `CapInh=0`
- `CapPrm=0`
- `CapEff=0`
- `CapAmb=0`
- Bounding set remained the platform process bounding set; it does not grant effective/permitted capabilities by itself.

The final target-files package had already proven:

- `/system_ext/bin/oxynoded` present
- `/system_ext/etc/init/oxynoded.rc` present
- `/system_ext/bin/oxynoded` file context `u:object_r:oxynoded_exec:s0`

## AVC interpretation

A logcat search for lines containing `oxynoded` found an AVC generated by the `shell` domain when validation attempted `ls -lZ /system_ext/bin/oxynoded`:

- source context: `u:r:shell:s0`
- target context: `u:object_r:oxynoded_exec:s0`
- denied operation: `getattr`

This is not an `oxynoded`-originated denial and is not a daemon failure. It demonstrates that the shell is not allowed to inspect the protected executable through that operation. The process itself was running normally in `u:r:oxynoded:s0`.

## Conclusion

S1.1 minimal `oxynoded` reintegration survives the Android 12 -> Android 14 migration on physical bramble hardware.
