## Effective packaging choices — NOT stock-super copyout

Oct11 operator runtime `/system_ext -> /system/system_ext` and `/product -> /system/product` is controlled by GSI `skip_mount.cfg`. The new payload must go into the **Android16 derived system.img embedded system_ext**, e.g. `/system/system_ext/priv-app/ImsService/ImsService.apk`, `/system/system_ext/framework/mediatek-{common,ims-base}.jar`, `/system/system_ext/lib64/` for any *admitted* system_ext native libs, and scoped permissions/sysconfig. **Standalone Android14 stock system_ext/product LP partitions in a hybrid super are not the source of effective IMS contents.** Original Oct11 **as-flashed super digest and fastboot journal are still UNBOUND**; retained offline R3 super is a byte/LP reference, not the physical Oct11 parent.

**APK shortlist:**
- Admit **C1 `ImsService.apk`** (qualified platform-resigned, shared UID, install path), and ensure the **already-present C3A MediaTek IMS telephony RRO** `treble-overlay-telephony-mtk-ims.apk` / package `me.phh.treble.overlay.mtkims_telephony` is actually built and enabled for `com.mediatek.ims`.
- Conditionally include **Sable-owned C2 readiness/init/config/marker modules** `SableTitan2Cellular`, `SableTitan2CellularInit`, `SableTitan2CellularConfig`, `SableTitan2CellularMarker` to measure MMTEL provider/UA readiness. Healer **shipped DISABLED by default**, no blind property/simswitch/reboot loop or force-start stock-disabled vendor UA.
- **Do not import** `MtkTeleService.apk`, `MtkTelephonyProvider.apk`, `MtkMmsService.apk`, `MtkTelecom.apk` or other OEM system replacement APKs without binding exact manifests, platform signing/UID/domain, installed provider/service collisions against Android16 TeleService/TelephonyProvider and a proven missing-owner case. No general stock `framework.jar`/`telephony-common.jar` copy.

**JAR shortlist:** two existing C1 MediaTek JARs **ADMIT**, with two configured boot-location overrides. Stock `mediatek-ims-common.jar`, `mediatek-ims-extension-plugin.jar`, `mediatek-telephony-common.jar`, `mediatek-telephony-base.jar`, `mediatek-framework.jar`, `mediatek-services.jar`, `mediatek-telecom-common.jar` and others are **OPTIONAL CANDIDATES NOT YET ADMITTED**; gate each by actual consumer/class descriptor/method/uses-library and effective BCP/SSCP/APEX classpath ownership. No extra JARs on bootclasspath from a filenames list.

**Native shortlist:** Use the EXACT reviewed C2 **28 stock + five platform-owner reuse** as a *coherent conditional candidate*, not naive 33-stock installation; derived candidate must independently resolve G3 full strong-symbol/version/recursive provider and effective privileged `com.mediatek.ims` namespace and Kati install-owner collisions. **The five already pinned R2 ViLTE libs are a subset of these 28 and not a separate extra five**. Existing 5 SHA/56 direct dependencies/19 Bionic/four direct GNU/six provider edges PASS original scope; complete effective image-bound G3 remains unproven. Reuse saved exact C2 hash manifests; do not re-materialize from stock just to recreate filenames.

**Call waiting has TWO SEPARATE mechanisms**:
1. **CW1** source patch against `GsmCdmaCallTracker.java` (old raw SHA `a57fbf4a4584b766a2b5eeab0dd88f0bf64ef644b2aec059ceb49bb8dee18ee8`) and `GsmCdmaConnection.java` (old raw SHA `026f9dd8f4661265e8ae19a85a492901bdd250850796f7472b1de2b2ffa4b6cf`). Four DEX methods `handleCallWaitingInfo(CdmaCallWaitingNotification)`, `onCreateGsmCdmaConnection(...)`, `notifyCallWaitingInfo(...)`, and call-waiting constructor. Verify exact original two-source blobs for new selected checkout and stock `invoke-super` consumer, apply the source patch only if PRE under new mutation approval. Do NOT transplant prior isolated `telephony-common.jar` binary across framework releases.
2. **Legacy IMS incoming call binder-thread compatibility** is already present in C3A but inert by default. C2 selects with product `ro.telephony.block_binder_thread_on_incoming_calls=false`, **without** a second telephony source patch. This setting is not proof of CW1 runtime semantics, VoLTE service or reliable radio registration.

## Proposed two-lane host candidate sequence (NON-FLASHABLE)

**A1 / First controlled cellular baseline:** new isolated Oct03 C3A-derived Android16 source checkout (not stale/canonical/M4/CW1 worktree) with preserved five Sable apps, existing GSI `skip_mount`, original PHH policy owners; R1 POST, B1 POST, six C1 IMS packages with cert+seinfo/BCP, PHH Titan guard/marker, enabled existing MTK IMS telephony RRO, C2 incoming call property and optional observe-only readiness package. Exact per-source PRE/POST checks before any mutations, no whole M4 C3B private-policy or stale root-directory fix import. Build host `systemimage` only after **separate exact source-mutation and host-build authorizations**, unique protected output. Result **NON_FLASHABLE** until boot critical gates.

**A2 / Expanded C2+CW1 follow-on within same isolate (conditional):** add the original CW1 two-source source patch **only if** source preconditions/consumer ABI match, and add C2 28 exact frozen stock native modules via fresh *selected target* collision and effective G3 qualification, retain the five Android16 platform providers. If selected-image recursive symbol/version/namespace G3 cannot close, retain A1 without native copyout; do not silently widen JAR/APK scope, build all 33 as prebuilts or pretend a compiled CW1 DEX means physical call waiting. Preserve distinct A1 vs A2 source/build/image seals for differential diagnosis. A single A2 build may replace an A1 build only after its stronger gates are closed; otherwise A1 is the next safe engineering sample.

**Offline hybrid LP assembly later**, only from an exact new image plus SHA-bound entire companion partition set and actual slot/VAB/AVB/restore geometry, with independent authorization. It is NOT automatically the unknown Oct11 physically flashed super. No full super/boot/vendor/vbmeta/slot modifications allowed now.

**Real cellular acceptance only after separate governed deployment and rollback**: IMS MMTEL registered; LTE/data in service stable ≥30min (Oct11 suffered transient-to-out-of-service); SMS/MMS both directions; outgoing/incoming voice, active-call incoming second call with call waiting/hold/resume/swap and carrier provisioning; no phone-process crash; three boots and reboot re-registration; later SIM tray2/DSDS. C1/C2 historically failed physical boot; M4 Recovery is not caused/proven cured by native/call-waiting expansion.
